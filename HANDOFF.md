**🚨 VERIFICATION-HARNESS RULE (learned the hard way 3×: 10.4 snapshots, Insights brief, M1 margin — the last cost 4 HOURS of silent hang).** ROOT CAUSE finally identified during M1: an uncaught top-level `throw` in a `vite-node` script does NOT exit the process (unlike plain Node) — the SSR module runtime stays resident forever, printing nothing. Every "hang" was likely this, not slow APIs and not stuck DB locks. **MANDATORY for every verification script from now on:** (1) wrap the whole body in try/catch with an explicit `process.exit(1)`; (2) wrap EVERY await in a hard per-step timeout that throws with the step name; (3) print a timestamped line BEFORE and AFTER every step; (4) run in the foreground under a pty. Also: if a verification run goes quiet for >10 min, KILL IT — do not wait on a notification.

**HARDENING #1 (gentler rebalancing — reduce churn) DONE + verified, committed (NOT pushed — Venky reviews, then push). No migration.** The thinker used to re-buy toward exact target weights every run (high turnover, and it ignored existing holdings entirely). Now it computes the MINIMAL trade set:

  - (1) DRIFT BAND / hysteresis: a TARGET position is only traded when its weight deviates from target by >5pp; within band → left alone (kills daily micro-churn).
  - (2) PREFER CASH over selling: underweight targets are filled with available agent_cash first (best quant score first); a held name is only TRIMMED if it's >5pp OVER target, and a name no longer in the target set is fully EXITED.

Inferred from `agent_decisions` where `action='sell'` (watchdog logs 'sell'; thinker trims/exits now log `action='trim'`, so 'sell' = watchdog only — NO new table/column needed). Skipped picks are LOGGED (`action='hold'`, "re-entry cooldown").
  - Guardrails enforced inside the planner: never spend below the cash buffer, never exceed max-position cap, never overspend agent_cash.
- `thinker.server.ts` rewired: reads current holdings + live prices, totalCapital = agent_cash + Σ(qty×price), filters cooldown out of targets (capturing dropped AI picks), calls `planRebalance`, executes (sells first then buys), seeds the trailing stop ONLY for brand-new positions (never lowers a ratcheted stop on an add). Rebalance decision rationale: "Portfolio within drift bands — no trades needed." when nothing material, else Claude commentary + "Adjusted N; held M within ±5pp band".
