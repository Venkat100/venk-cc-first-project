  - **`lib/insights/eventstudy.server.ts` (new, pure + unit-tested):** exact definitions, documented in the file header. A "shock" on day *i* is a daily return `|r_i| > 2σ`, where σ is the standard deviation of the TRAILING 60 daily returns strictly BEFORE day *i* (no look-ahead; needs ≥20 trailing returns before a threshold is computed at all). Direction: `r_i > 0` → up-shock, `r_i < 0` → down-shock. For each qualifying shock, measures the +5-trading-day ("1 week") and +21-trading-day ("1 month") forward returns — an event only counts once BOTH forward windows are fully realized in the data (a shock from 10 days ago isn't half-counted with a missing 1-month figure; it's excluded from both until it has a full month behind it, so the 1-week and 1-month stats always describe the identical population of events). Aggregates `{ events_found, avg_fwd_1w, median_fwd_1w, avg_fwd_1m, median_fwd_1m, worst_1m, best_1m, pct_positive_1m }` separately for up-shocks and down-shocks; `window_years` is the ACTUAL span of data used (computed from the candles' own first/last dates), so a recent IPO honestly reports a short window instead of a padded one. `getMeasuredHistory(symbol, direction)` fetches ~5Y of daily candles via the EXISTING `providerSeries` (Twelve Data, already used by charts/simulator — no new provider) and returns the stats for the requested direction; on any provider failure it throws and the caller degrades to `null` rather than fabricating a number.
  - **Wired into `getStockInsight` (`insights.server.ts`):** direction is chosen from the stock's own live `day_change_pct` sign (up day → look up its up-shock history; down day → down-shock history) — a simple, deterministic, already-available signal, not a separate judgment call.
